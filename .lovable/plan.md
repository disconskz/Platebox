## Цель

Перевести спецоперации обложки (начиная с «Выборочный лак») на полноценную ERP-структуру: 4 составляющих (материал, работа, приладка, оснастка), справочник лаков с CRUD, коэффициент по тиражу, скрытие технических деталей за тумблером.

## 1. Справочник лаков (БД)

Новая таблица `varnish_types` (CRUD на странице «Справочники»):
- `name` — наименование лака
- `material_price_per_m2` — цена лака, ₸/м²
- `work_price_per_sheet` — стоимость работы, ₸/лист
- `setup_price` — стоимость приладки, ₸
- `tooling_price` — стоимость формы (оснастки) по умолчанию, ₸
- `circulation_coef` (jsonb) — коэффициенты по диапазонам тиража, например:
  `[{"min":0,"max":500,"k":1.3},{"min":501,"max":2000,"k":1.0},{"min":2001,"max":null,"k":0.85}]`
- `is_active`, `sort_order`

Раздел «Лаки» появится в `/references` рядом с `press_machines`, с полным CRUD. Сидим 2-3 пресета (выборочный матовый, глянцевый, 3D).

## 2. ERP-формула операции (общая для всех спецопераций обложки)

```text
Итого = Материал + Работа + Приладка + Оснастка
Материал  = площадь_покрытия_м² × цена_материала_₸/м² × k_тираж
Работа    = (печатные_листы + приладочные_листы) × тариф_работы_₸/лист × k_тираж
Приладка  = setup_price (фикс)
Оснастка  = tooling_price (фикс, форма/штамп/клише)
```

- Формула считается «новой формой» по умолчанию (оснастка включается всегда), при повторе можно снять чекбокс «Новая форма» — тогда оснастка = 0.
- `печатные_листы + приладочные_листы` берётся из текущего движка обложки (он уже считает `printSheets` с учётом приладки).
- `k_тираж` — коэффициент из справочника, выбирается по тиражу обложки.
- Все «Подрядчики» убираются из полей и маршрута.

## 3. UI обложки — переработка

**Глобальный тумблер** «Показать детали расчёта» сверху раздела «Спецоперации обложки». По умолчанию — ВЫКЛ. Когда выкл:
- В каждой включённой операции виден только заголовок + 4 строки итога: Материал / Работа / Приладка / Оснастка / **Итого**.
- Скрыты: тарифы, формулы, коэффициенты, поля редактирования, ссылки на справочник.

Когда вкл — раскрываются индивидуальные блоки (плюс у каждой операции есть свой тумблер «детали» для тонкого управления).

**Карточка «Выборочный лак»** при включённой галочке:
- Селектор «Тип лака» (из справочника `varnish_types`).
- Чекбокс «Новая форма» (по умолчанию ✓).
- Поле «Площадь покрытия лаком, %» (по умолчанию 100% от листа) — на её основе считается м².
- Если детали ВКЛ — показываются цена лака ₸/м², тариф работы ₸/лист, приладка, форма, k тиража, формула.
- Поле «Подрядчик» убирается из секции печати.

**Остальные спецоперации** (тиснение, конгрев, УФ, выборочный лак, скругление, вырубка, окно, фигурная высечка, припресс плёнкой, биговка) переводятся на ту же структуру 4-х составляющих. Где нет физического материала (напр. биговка) — материал = 0; где нет оснастки — оснастка = 0. Остальные параметры остаются в их «справочниках» (для лаков — БД, для прочих — текущий каталог).

## 4. Движок себестоимости (`src/lib/calc/cover/cost.ts`)

`buildCoverLines` для каждой включённой спецоперации добавляет 4 строки в правильные стадии:
- «Материалы» → материал
- «Постпечать обложки» → работа
- «Постпечать обложки» → приладка (1 усл.)
- «Допечатка обложки» → оснастка/форма (1 усл., только если «Новая форма»)

Все формулы используют `printSheets` (он = чистые + приладочные). Премиум-коэф. (soft-touch и пр.) сохраняется как множитель работы.

## 5. Технические детали

Файлы:
- `supabase/migrations/*` — новая таблица `varnish_types` + GRANT + RLS (read для authenticated, write для admin) + 3 сид-записи через INSERT.
- `src/integrations/supabase/types.ts` — авто-генерация после миграции.
- `src/pages/References.tsx` — новый раздел «Лаки» (по образцу `press_machines`).
- `src/components/calc/multipage/sections/CoverSection.tsx`:
  - `CoverState`: новые поля `showCalcDetails: boolean`, `specOps[*].varnishTypeId`, `specOps[*].newTooling`, `specOps[*].coverageAreaPct`, `specOps[*].material`, `specOps[*].work`, `specOps[*].toolingPrice`, `specOps[*].setupPrice`.
  - Удаление `contractor` из UI.
  - Глобальный `Switch` «Показать детали расчёта».
  - Новый рендер карточек с 4-блочным итогом.
- `src/components/calc/multipage/sections/CoverSection.tsx` экспортирует обновлённый `COVER_SPEC_OP_CATALOG` со структурой `{ material, work, setup, tooling }` (числа по умолчанию).
- `src/lib/calc/cover/cost.ts`:
  - Новая функция `coverSpecOpBreakdown(key, params, ctx, varnishLookup)` возвращающая `{ material, work, setup, tooling, total }`.
  - `buildCoverLines` пушит 4 строки на операцию.
  - `buildCoverWarnings` без изменений по сути.
- Хук загрузки `varnish_types` — клиентский запрос на supabase в `CoverSection` (как уже делается в `Calculator.tsx` для прочих справочников).

Поведение сохранения старых калькуляций: дефолты в стейте подставляются через `{ ...DEFAULT_COVER, ...value }`, поэтому существующие записи не сломаются.

## 6. Шаги реализации

1. Миграция: таблица `varnish_types` + GRANT + RLS + сиды.
2. Раздел «Лаки» в `/references`.
3. Рефакторинг `CoverState` и `COVER_SPEC_OP_CATALOG` под 4-блочную структуру.
4. Перевод `cost.ts` на новую формулу + удаление поля «Подрядчик» из UI/маршрута.
5. UI: глобальный тумблер «Показать детали», карточка «Выборочный лак» с селектором лака и «Новая форма», унифицированный рендер для остальных операций.
6. Проверка превью.
