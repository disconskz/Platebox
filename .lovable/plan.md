## Задача

Сейчас в шаблонах (Брошюра, Блокнот, Календарь настольный/карманный и т.д.) встроенные операции (ламинация, биговка, перфорация, нумерация, тиснение, сшивка, фальцовка, упаковка и т.д.) считаются по **захардкоженным** ценам и формулам в коде. В справочнике (`operation_catalog` + `operation_work_items` + `operation_parameters`) для большинства из них уже есть готовые формулы. Нужно, чтобы каждая встроенная операция шаблона **по умолчанию считалась по формуле из справочника**, а захардкоженные значения остались только как fallback.

## Подход

### 1. Слой соответствий «операция шаблона → код справочника»

Создаём новый файл `src/lib/operations/templateOpsMap.ts`:

- Таблица `TEMPLATE_OP_MAP`: ключ — стабильный `opKey` встроенной операции (`coverLam1`, `coverLam2`, `coverBig`, `stamp`, `emboss`, `perf`, `num`, `dieCut`, `varnish`, `spotVarnish`, `fold`, `gather`, `staple`, `eurostaple`, `kbs`, `thermo`, `spiral`, `pva`, `sewn`, `trim`, `pack`, ...), значение — `operation_catalog.code` + словарь `paramMap` (имя переменной из формулы → как взять из контекста шаблона: `circulation`, `printSheets`, `signatures`, `perfLines * circulation`, и т.п.).
- Это позволит единым местом расширять связи без правки 40 файлов калькуляторов.

### 2. Хелпер `useHandbookPricing()`

Файл `src/lib/operations/useHandbookPricing.ts`:

- Один раз грузит из Supabase `operation_catalog / operation_work_items / operation_parameters` и кеширует через React-context (`HandbookProvider` в `App.tsx`), чтобы шаблоны не запрашивали справочник по 30 раз.
- Возвращает функцию `priceOp(opKey, ctx)` → массив `SpecItem[]` (одна операция → несколько строк work_items, как сейчас в `CatalogOperationsPicker`).
- Если для `opKey` нет связки в `TEMPLATE_OP_MAP`, либо у операции нет `work_items`, либо формулы не парсятся — возвращает `null`, и шаблон использует свой fallback-расчёт.
- Использует существующий `evalFormula` из `src/lib/operations/formula.ts`.

### 3. Внедрение в шаблоны

Для каждого шаблона из уже подключённых (`Brochure`, `Notepad`, `DeskCalendar`, `PocketCalendar`, `Calculator`) меняем `push("Постпечать", "Ламинация обложки ...", qty, unit, price)` на:

```ts
const fromHandbook = priceOp("coverLam", { 
  "Количество бумаги на тираж": coverLayout.printSheets,
  "Количество прогонов": coverLamSides,
  "Цена за лист": coverLamPricePerSheet, // fallback-цена остаётся
});
if (fromHandbook) out.push(...fromHandbook);
else push("Постпечать", "Ламинация обложки", ..., 220);  // старый fallback
```

Захардкоженные блоки остаются как **fallback**, чтобы при пустом справочнике или незаполненной формуле калькулятор продолжал работать.

### 4. Индикация источника цены

В `LineItemsTable` (и/или таблице итогов) к строке добавляем маленькую пометку «из справочника» / «по умолчанию», чтобы пользователь видел, какие операции уже подтянулись. Реализуем через дополнительное необязательное поле `SpecItem.source` ('handbook' | 'default').

### 5. Поэтапный rollout

Согласно прошлой договорённости — поэтапно:

1. **Брошюра** — образец (включая твёрдый переплёт, ежедневник, журнал, каталог-флаги внутри файла).
2. Блокнот, Календарь настольный, Календарь карманный.
3. Книги (Hardcover/Softcover), Журнал, Каталог.
4. Коробки (BoxPro, Box).
5. Остальные (буклеты, листовки, визитки, открытки, конверты, папки, наклейки, плакаты, бланки, прочие).

Каждый этап = отдельный коммит после ревью. По умолчанию начинаю со **шага 1 (Брошюра)** и останавливаюсь для проверки результата, потом продолжаю.

## Технические детали

- Контекст справочника: новый `HandbookProvider` в `src/components/calc/HandbookProvider.tsx`, оборачиваем в `App.tsx`.
- Имена переменных в формулах справочника на русском (`[Количество бумаги на тираж]`, `[ТИРАЖ]`, `[количество бигов общее за тираж]`). `paramMap` в `TEMPLATE_OP_MAP` приводит их к значениям из локального контекста шаблона.
- `CatalogOperationsPicker` остаётся для **ручного** добавления операций, которых нет среди встроенных.
- Никаких миграций БД не требуется — структура справочника уже подходит.
