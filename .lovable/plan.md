## Что строим

Новый режим калькулятора **«Много SKU / Групповой спуск»**, который позволяет рассчитать тираж из нескольких разных видов изделий, печатающихся вместе на одном печатном листе (один лист = один спуск).

Технологическое ограничение: на одном спуске возможны разные **дизайны (SKU) и индивидуальные тиражи**, но общие — материал, красочность, печатный/закупочный формат, постпечать. Эти параметры остаются на уровне всего расчёта; per-SKU задаются только: имя, формат изделия (Ш×В), тираж.

## UX (шаги в Calculator)

**Шаг 1 — Тип продукта**: добавляется тумблер «Один вид / Много видов (групповой спуск)».

**Шаг 2 — Список SKU** (только в режиме «Много видов»): таблица с колонками Имя · Ширина (мм) · Высота (мм) · Тираж · ✕. Кнопка «+ Добавить вид». Подсказка HelpHint с примером (30 видов A6 → 8 шт/лист → 4 спуска).

**Шаг 3 — Материал/красочность/постпечать**: как сейчас, общие для всех SKU.

**Шаг 4 — Результат**: вместо одной карточки показываем **две карточки сравнения**:

```text
┌─ Вариант A: Минимум форм ────┐  ┌─ Вариант B: Без пустот ──────┐
│ Спусков: 4                   │  │ Спусков: 5                   │
│ Форм: 4 × красочность        │  │ Форм: 5 × красочность        │
│ Приладочных листов: …        │  │ Приладочных листов: …        │
│ Печатных листов: …           │  │ Печатных листов: …           │
│ Пустых позиций на листе: 2   │  │ Пустых позиций: 0            │
│ Себестоимость: 123 456 ₸     │  │ Себестоимость: 119 200 ₸ ✓   │
│  [ Применить ]               │  │  [ Применить ]               │
└──────────────────────────────┘  └──────────────────────────────┘
```

Дешёвый вариант помечается галочкой/бейджем «Выгоднее на X ₸». Менеджер кликает «Применить» — тогда показывается обычная подробная спецификация и кнопка «Сохранить расчёт».

## Алгоритм расчёта (engine)

Новая функция `runMultiSkuCalculation(input)`:

1. **Раскладка**: подобрать оптимальный печатный формат (рабочие 460×320 / 520×360) исходя из *самого крупного* SKU; рассчитать `slotsPerSheet` — сколько позиций (ячеек) помещается на листе. Все SKU считаются занимающими одинаковую «ячейку» по габариту самого крупного — это упрощение, согласованное с предметной областью.
2. Подсчитать `totalSkus = N` (число видов).
3. **Вариант A (минимум спусков, с пустотой)**:
   - `impositionsA = Math.ceil(totalSkus / slotsPerSheet)`
   - Последний спуск: `slotsUsedLast = totalSkus - (impositionsA-1) * slotsPerSheet`, остальные позиции пустые.
   - Каждое SKU печатается тиражом своего вида → для каждого спуска печатных листов = `max(тиражей SKU на этом спуске) / 1` (поскольку один отпечаток даёт по одной копии каждого SKU из спуска; если тиражи разные — печатаем по максимуму, остальные SKU допечатываются с избытком, который идёт в отход — это упрощение MVP).
   - Альтернативная и более точная модель: печатных листов на спуск = `ceil(maxTirazhSku / 1)`, излишки фиксируем в `wastedItems`.
   - Для каждого спуска: формы = красочность (свой оборот) или 2× (чужой), приладочные листы по существующему правилу.
   - Суммируем: `formsTotal`, `setupSheetsTotal`, `printSheetsTotal`, `paperCost`, `printCost`, `formsCost`, `formsPrepCost` + постпечать.
4. **Вариант B (без пустот, больше спусков)**:
   - Перебираем `impositions = impositionsA, impositionsA+1, …, impositionsA+K` (K=3-5).
   - На каждом значении проверяем, можно ли распределить SKU по спускам так, чтобы все позиции каждого спуска были заполнены (greedy: разбить SKU на группы; повторение SKU допускается, чтобы добить пустоты — это и есть «доп. оттиски на тех же формах»).
   - Считаем стоимость для каждого варианта и выбираем минимальный по полной себестоимости.
   - Если разница с Вариантом A < 1% или B = A → показываем только A.
5. Возвращаем `{ variantA, variantB }` — обе со своей spec для последующего отображения.

## Что НЕ входит в этот этап

- Гео-оптимизация раскладки разных по габаритам SKU на листе (mixed-size bin packing). Используется упрощение «все SKU занимают ячейку максимального габарита». В UI пишем ворнинг, если SKU сильно различаются по размеру.
- Сохранение группового расчёта как нескольких отдельных — сохраняется один с массивом SKU.
