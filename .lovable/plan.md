## Цель

Сейчас карточка «Распознанный заказ» показывает только параметры продукта и итог. Нужно дать менеджеру всю «механику» расчёта: на какой машине печатаем, какой печатный лист, сколько физических листов с приладкой, сколько штук на лист, разбивку постпечати и налогов.

## Что меняем

### 1. Edge function `supabase/functions/ai-calc-chat/index.ts`

Расширяем JSON-схему `proposed_order`, чтобы модель присылала «производственные» поля:

- `press_machine_name` — название машины (из справочника по `press_machine_id`)
- `print_format_label` — печатный лист, напр. `640×920 (A2+)`
- `purchase_format_label` — закупочный лист
- `items_per_sheet` — штук на лист (раскладка)
- `sheets_total` — всего листов
- `sheets_setup` — листов приладки
- `sheets_useful` — полезных листов
- `material_price_per_sheet` — цена за лист бумаги
- `impressions` — количество оттисков (`sheets_total × max(color_front, color_back)`)
- `cost_per_impression` — себестоимость одного оттиска
- `setup_cost` — стоимость приладки машины
- `form_cost_total` — стоимость форм (если применимо)
- `postpress_breakdown` — массив `{ name, qty?, unit?, cost }` для ламинации, фальцовки, высечки, нумерации, тиснения, резки
- `vat_percent`, `vat_amount`, `margin_percent`, `margin_amount` — для прозрачности

Обновляем `BASE_SYSTEM_PROMPT`: добавляем эти поля в схему + правило заполнять их, опираясь на `press_machines` / `print_formats` / `purchase_formats` / `operations` из справочника. Расширяем `sanitizeProposedOrder` — резолвим `press_machine_name` и `print_format_label` на сервере из снапшота (надёжнее, чем верить модели), чтобы клиент гарантированно получил подписи.

### 2. Тип `ProposedOrder` в `src/components/ai-calc/ChatWindow.tsx`

Добавляем те же опциональные поля в TS-тип.

### 3. UI карточки `ProposedOrderCard` в том же файле
