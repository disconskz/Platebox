
# Конструктор вариантов просчёта — Фаза 1

Реализуем разделы ТЗ **1–4, 6, 7** ТЗ. Старый калькулятор остаётся как есть; новый конструктор живёт параллельно. Условия if/else (раздел 5) и версионирование (8) — отдельными фазами.

## Что появится у пользователя

1. **Новый раздел «Варианты просчёта»** в Справочниках. Таблица созданных вариантов: название, базовая категория, число этапов, действия (создать / редактировать / дублировать / удалить).
2. **Редактор варианта** — три блока:
   - *Этапы работы* — список этапов с drag-and-drop. Для каждого: название, единица измерения, формула (визуальный конструктор), привязка к материалу (опционально). Этап можно «достать из библиотеки» (типовые этапы: дизайн, СТР, резка, печать офсет, перфорация, склейка блока и т.д.) или создать с нуля.
   - *Материалы* — выбор из справочника бумаг/расходников + формула расхода (`закуп_листов`, `тираж × норма` и т.п.).
   - *Тестовый прогон* — вводишь тираж, формат, плотность, нажимаешь «Посчитать» и видишь разбивку по этапам + итог. Используется для проверки формул до сохранения.
3. **Справочник констант** — новая вкладка в Справочниках. Таблица: параметр / значение / ед. изм. / описание. Заводские константы (цена формы, оттиска, резки, краски, приладка, накладные, доставка) + возможность добавить свои.
4. **Интеграция в калькулятор** — в выпадающем списке «Вид продукции» появляются пользовательские варианты (с пометкой). При выборе калькулятор переходит в «режим конструктора»: показывает форматы/тираж/материал из движка, считает раскладку существующим алгоритмом, подставляет переменные в формулы варианта и выводит итог.

## Визуальный конструктор формул

Каждая формула — последовательность блоков, рисуемых чипами:

```text
[ кол_форм ] [ × ] [ const: Цена формы ] [ + ] [ приладка ]
```

Типы блоков: **Переменная** (синяя), **Константа** (зелёная, ссылка по slug в справочник), **Число**, **Оператор** (+ − × ÷), **Функция** (`min`, `max`, `ceil`, `floor`, скобки). Под полем — живой предпросмотр результата на тестовых данных. Внутри хранится AST в JSON (см. ниже), отображается в виде чипов; всегда есть кнопка «как формула» — показывает строковое представление.

## Гибридные переменные

Перед вычислением формул движок прогоняет существующий `runCalculation` для базовой категории варианта (выбирается при создании, напр. «листовка»). Полученные значения автоматически становятся переменными:

- `тираж`, `сторон`, `плотность` — из параметров заказа
- `печ_листов`, `закуп_листов`, `кол_форм`, `приладка`, `кол_резов`, `площадь_печати` — из результата раскладки
- `кол_блоков` — отдельное ручное поле в калькуляторе для блочных вариантов

Любую авто-переменную можно переопределить вручную галочкой «задать самому» в шаге калькулятора.

## Технические детали

### Схема БД (новая миграция)

- `calc_variants` — `id`, `name`, `description`, `base_product_type` (ссылка на существующий ProductType для движка раскладки), `category`, `is_active`, `sort_order`, `created_at`, `updated_at`. RLS: read для authenticated, write для admin.
- `calc_variant_stages` — `id`, `variant_id` FK, `name`, `unit`, `formula` jsonb (AST), `material_id` nullable FK, `material_formula` jsonb nullable, `sort_order`.
- `calc_constants` — `id`, `slug` unique, `name`, `value` numeric, `unit`, `description`. RLS аналогично. Сидируем дефолтами из ТЗ.
- `calc_stage_library` — каталог типовых этапов (название + дефолтная формула в JSON). Сидируем 10–15 строк из примера ТЗ.

### Формат формулы (AST)

```json
{
  "op": "+",
  "args": [
    {"op": "*", "args": [{"var": "кол_форм"}, {"const": "form_cost"}]},
    {"var": "приладка"}
  ]
}
```

Узлы: `{var}`, `{const}`, `{num}`, `{op, args[]}`, `{fn, args[]}`. Эвалюатор — собственный (без `eval`/mathjs зависимости), ~80 строк.

### Что НЕ делаем в этой фазе

- Условия `if/else` (раздел 5 ТЗ) — будет в следующей фазе после обкатки.
- Версионирование вариантов и привязка старых расчётов к версии (раздел 8) — отдельная задача; пока редактирование варианта меняет его «на месте» с предупреждением.
- Накладные расходы как процент от суммы — выносим в константу `overhead_percent`, но автоматическую строку в калькуляторе не добавляем.
