## Конструктор формул в справочнике «Виды работ»

Сейчас формулы операций (`operation_work_items.price_source` / `quantity_source` и `operation_parameters.formula` / `default_value`) только отображаются. Менеджер не может их менять — для 16 операций они вообще пустые. Добавим UI-конструктор, чтобы админ сам собирал формулы из переменных, констант и арифметики, без кода и без знания SQL.

## Что увидит пользователь

В правой панели `Справочники → Виды работ (формулы)` каждая операция станет редактируемой:

1. **Параметры операции** — редактируемая таблица:
   - название, значение по умолчанию (число, `[ТИРАЖ]` или формула), формула (необязательная), заметка
   - кнопки «+ параметр», «удалить», drag-сортировка
2. **Статьи стоимости работ** — таблица с двумя формулами на строку: «Цена» и «Количество», + итог.
3. **Кнопка «Изменить формулу»** открывает модальный **конструктор формул**.

### Конструктор формул (модалка)

Три блока в одном окне:

```text
┌─────────────────────────────────────────────┐
│ [ Кол-во ударов ] × [ Цена удара ] + 5000   │  ← превью-чипы
├─────────────────────────────────────────────┤
│ [+ Переменная ▾] [+ Константа ▾] [+ Число] │
│ [ + ] [ − ] [ × ] [ ÷ ] [ ( ] [ ) ]         │
│ [ ⌫ Удалить ] [ Очистить ]                  │
├─────────────────────────────────────────────┤
│ Проверка: подставить ТИРАЖ = 1000 → 8 240 ₸ │
└─────────────────────────────────────────────┘
```

- **Переменные** — выпадающий список со всеми параметрами текущей операции + спецтокены `ТИРАЖ`, `ПРЕДЫДУЩЕЕ ЗНАЧЕНИЕ`. Вставляются как чип `[Имя]`.
- **Константы** — из таблицы `calc_constants` (например, «Стоимость клише за см²»). Вставляются как чип `{slug}` и при сохранении превращаются в число.
- **Числа** — инлайн-ввод.
- **Операторы** — кнопки.
- **Превью-результат** — внизу окна показываем, во что вычисляется формула при тестовом тираже (используем существующий `evalFormula`).
- **Скобки** автоматически балансируются — кнопка `( )` оборачивает выделенные чипы.

При сохранении конструктор сериализует чипы в строку формата, который уже понимает `src/lib/operations/formula.ts` (`[Имя] * [Цена] + 5000`) — никакой миграции данных не нужно.

### Поддержка условий (опционально, в первой версии не делаем)

Если в будущем понадобятся ветки «если тираж > 1000 → …», добавим блок `Если … то … иначе …` и расширим evaluator. Сейчас все 50 загруженных формул — линейные, этого достаточно.

## Где это живёт в коде

- **UI**: новый компонент `src/components/references/FormulaBuilder.tsx` (диалог) + переписать `OperationCatalog.tsx` так, чтобы таблицы параметров/статей стали редактируемыми, а ячейки формул открывали билдер.
- **Сериализация**: `src/lib/operations/formula-builder.ts` — функции `tokensToString(tokens)` / `stringToTokens(s, vars, consts)` поверх существующего `extractVariables` и `evalFormula`.
- **Сохранение**: прямой `upsert/delete` в `operation_parameters` и `operation_work_items` (RLS уже разрешает админу).
- **Доступ**: пишет только админ (`has_role admin`), как и сейчас. Менеджер — только читает.
- **Согласованность движка**: серверный порт `supabase/functions/ai-calc-chat/formula.ts` уже один-в-один с клиентом, новых изменений в edge-функции не нужно.

## Технические детали

Структура токена в редакторе:

```ts
type Token =
  | { kind: "var"; name: string }          // → [Имя]
  | { kind: "const"; slug: string; value: number; label: string } // → число (с подсказкой)
  | { kind: "num"; value: number }         // → 123.45
  | { kind: "op"; op: "+" | "-" | "*" | "/" | "(" | ")" };
```

Валидация перед сохранением:
- сбалансированные скобки;
- нет двух операторов подряд;
- `evalFormula(serialized, { ТИРАЖ: 1000, ...defaults })` возвращает `ok: true` (или `missing` пуст для параметров без зависимостей).

## Что НЕ входит в этот шаг

- Создание новых операций «с нуля» в каталоге (отдельная задача).
- Условные формулы (`if/else`, `CASE WHEN`).
- Версионирование формул и история изменений.
- Импорт/экспорт справочника.

## Готовность

После этого администратор:
1. Открывает «Виды работ (формулы)» → выбирает, например, «Печать односторонняя».
2. Нажимает «+ статья» → пишет название → нажимает «Изменить формулу цены» → собирает `[Кол-во оттисков] × [Цена оттиска]` мышкой → видит превью → сохраняет.
3. Калькулятор сразу подхватывает новую формулу (`CatalogOperationsPicker` уже читает из тех же таблиц).
