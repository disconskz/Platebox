## Цель

Добавить глоссарий из ~100 видов печатной продукции с описаниями. Каждая позиция должна:
1. Существовать как тип в калькуляторе (выбираться на шаге 1).
2. Иметь короткое описание, видимое в карточке выбора **и** в tooltip (HelpHint).
3. Храниться централизованно в новой системной таблице `product_glossary` (админ-управляемой), доступной всем как справочник.

## Архитектура

### 1. БД — новая таблица `product_glossary`
Поля:
- `slug` (text, unique) — машинное имя (например, `flyer`, `eurofly`, `box_magnetic`)
- `name` (text) — отображаемое имя («Флаер»)
- `description` (text) — текст из ТЗ
- `category` (text) — группа: `print_small`, `multipage`, `calendar`, `pos`, `packaging_box`, `packaging_bag`, `document`, `large_format`, `souvenir`, `other`
- `base_product_type` (text, nullable) — связь с существующим расчётным движком (`leaflet`, `booklet`, `box`, `sticker`, `bag`, …). Если NULL — позиция ещё не имеет формул и помечается «расчёт по аналогу/по запросу».
- `is_calculable` (bool) — true если можно считать через движок (т.е. base_product_type заполнен)
- `sort_order` (int)

RLS: чтение всем authenticated, запись только admin (по образцу `materials`/`format_presets`).

Миграция засевает все ~100 позиций из ТЗ (одним INSERT с маппингом slug→base_product_type для известных, NULL для нестандартных).

### 2. Маппинг к существующим типам калькулятора
Не плодить 100 ветвей в `engine.ts`. Вместо этого:
- Калькулятор по-прежнему оперирует базовыми `ProductType` (24 шт. в `src/lib/calc/products.ts`).
- Глоссарий-позиция хранит `base_product_type`. При выборе из глоссария калькулятор подставляет соответствующий базовый тип, а название и описание показывает из глоссария.
- Позиции без `base_product_type` (например, «Пресс-волл», «Холст», «Роллап», «Ростовая фигура») — отображаются с бейджем «Расчёт по запросу» и кнопкой «Запросить расчёт» (создаёт черновик, без автоматики).

Грубое распределение:
- `leaflet` → Листовка, Флаер, Еврофлаер, Афиша, Вкладыш, Купон, Анкета, Меню (1 лист)
- `businesscard` → Визитка, Карманный календарь, Бирка, Бирка на одежду, Ценник, Бейдж
- `booklet` → Буклет, Триплет, Лифлет
- `brochure` → Брошюра, Каталог, Инструкция, Чековая книжка
- `book`, `magazine`, `notepad` → как есть + Ежедневник, Тетрадь → notepad
- `calendar_*` → соответствующие календари
- `sticker`/`sticker_diecut` → Наклейка, Стикер, Этикетка, Магнит, Наклейка на авто
- `label` → Этикетка
- `poster` → Плакат, Постер
- `wobbler`, `shelftalker` → как есть; Хенгер, Тейблтент, Мобайл, Менюхолдер → ближайший POS
- `envelope` → Конверт, Приглашение, Открытка (если плоская)
- `folder` → Папка, Сертификатная папка, Сертификат, Диплом, Грамота, Бланк
- `selfcopy` → Самокопирующийся бланк
- `bag` → все 3 пакета
- `box`, `kubus` → коробки/упаковки/пенал/тубус/шоу-бокс/обечайка/шубер/слипкейс/бирдекель/пазл и все «Упаковка для …», «Коробка для …»
- Без базового типа (на запрос): Баннер, Роллап, Пресс-волл, Фотозона, Холст, Ростовая фигура, Дисплей, Табличка, POS-материал (общий)

### 3. Frontend

**Шаг 1 калькулятора (`Calculator.tsx`, `MultiSkuCalculator.tsx`):**
- Загрузка `product_glossary` вместо хардкод-списка из `PRODUCT_LABELS`.
- Селектор продукта → группированный по `category` поиск/комбобокс с:
  - название
  - подпись (description, обрезанная) серым `text-muted-foreground` под названием
  - иконка ⓘ HelpHint справа с полным описанием
  - бейдж «По запросу» если `!is_calculable`
- При выборе non-calculable — показать сообщение и блокировать «Рассчитать».

**Новый справочник `/references` → таб «Глоссарий продукции»:**
- Таблица: name / slug / category / base_product_type (select из существующих) / is_calculable / description (textarea) / sort_order.
- CRUD только для admin; остальные видят readonly.
- Поиск по name/description.

**Knowledge.tsx:**
- Раздел «Глоссарий продукции» со списком, сгруппированным по category, с описаниями (читается из той же таблицы).

### 5. Что НЕ делаем (вне scope)
- Не пишем формулы расчёта для новых базовых типов (баннер, холст, пазл и т.п.) — они помечаются «по запросу».
- Не меняем ценообразование/материалы для существующих типов.
- Не делаем мультиязычность описаний (только RU).

## Проверка
- 49 существующих тестов должны проходить.
- В калькуляторе селектор показывает все 100 позиций с описаниями и поиском.
- Выбор «Флаер» → внутри считается как `leaflet` без регрессий.
- Выбор «Пресс-волл» → блокирует расчёт с сообщением «По запросу».
- В админ-панели справочника можно отредактировать описание, оно сразу обновляется в калькуляторе.
