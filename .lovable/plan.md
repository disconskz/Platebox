# План переработки ERP-архитектуры многостраничных изделий

ТЗ объёмное (33 раздела), затрагивает архитектуру, UI, движок расчёта, маршруты и отчёты. Разобью на 6 этапов. После каждого этапа — пауза, проверка, переход к следующему. Начну с фундамента (модель данных + режимы), без него остальное смысла не имеет.

## Затрагиваемые типы изделий
brochure, magazine, catalog, book, book_hardcover, notepad, planner, calendar_* — всё, что идёт через `MultipageTemplateHost` и `BrochureCalculator`.

---

## Этап 1 — Фундамент: режимы интерфейса + глобальные параметры (разделы 2, 3, 4, 5, 6)

**Цель:** убрать дублирование, ввести 3 режима, ввести наследование сверху вниз.

- Новый контекст `MultipageCalcContext` с глобальными параметрами: формат, тираж, ориентация, тип печати, тип сборки, срок, наценка.
- Хук `useInheritedParam(localValue, override)` — возвращает глобальное значение, пока не включён флаг "Переопределить".
- Переключатель режимов «Простой / Расширенный / Технологический» (сохраняется в localStorage, по умолчанию — Простой).
- Обёртки `<SimpleOnly>`, `<AdvancedOnly>`, `<TechOnly>` для условного рендера секций.
- В `BrochureCalculator` и `NotepadCalculator` убрать локальные поля формата/тиража/печати из дочерних блоков — они приходят из глобальных.
- Кнопка «Переопределить параметры блока» открывает локальные поля.

## Этап 2 — Архитектура внутренних блоков (разделы 7, 8, 9, 10, 11)

- Заменить текущую секционную структуру в `BrochureCalculator` на массив «Внутренних блоков» с кнопкой «➕ Добавить блок».
- Каждый блок: бумага, плотность, кол-во листов, цветность, тип печати (с наследованием), операции, **тип блока** (dropdown: основной / вставка / разделитель / калька / рекламный / форзац / спецсекция).
- Drag-and-drop порядка блоков (опционально, или стрелки ↑↓).
- Миграция: текущая `pages`/`coverPages` маппится в 1 «основной» блок при загрузке.

## Этап 3 — Реструктуризация порядка секций (разделы 12-21)

Перестроить вертикальный порядок секций в шаблонах:

1. Основные параметры → 2. Обложка → 3. Подложка → 4. Внутренние блоки → 5. Допечатка → 6. Печать → 7. Постпечатка → 8. Сборка → 9. Спецоперации → 10. Контроль качества → 11. Упаковка → 12. Маршрут → 13. Итог → 14. Тех. отчёт.

- Создать недостающие секции: **Допечатка** (препресс, формы, DXF/SVG, QR, переменные данные), **Контроль качества**, **Упаковка**.
- Перенести «Сборку» после «Постпечатки», «Спецоперации» после «Сборки».
- Каждая секция — отдельный компонент в `src/components/calc/multipage/sections/`.

## Этап 4 — Динамический маршрут + предупреждения (разделы 22-26)

- Движок `buildRoute(blocks, options)` в `src/lib/calc/multipage/route.ts`: формирует упорядоченный список операций, скрывает ненужные (нет ламинации → нет биговки и т.д.).
- Компонент `<RouteTimeline>` в секции «Маршрут».
- Модуль `validateTech(state)` → массив предупреждений (`⚠ Ламинация без биговки`, `⚠ Блок толще пружины` и т.д.). Рендер в баннере над «Итогом».
- Автоподбор пружины: функция `pickSpring(blockThicknessMm)` → диаметр, длина, доступные цвета.

## Этап 5 — Состав изделия + технологический отчёт (разделы 27-30)

- Компонент «Состав изделия» — таблица (Деталь / Материал / Кол-во / Операции), генерируется из state. Виден в Расширенном+.
- «Технологический отчёт» — секции Материал / Спуск / Печать / Постпечатка / Маршрут с фактическими цифрами из `result`. Только Тех. режим.
- Скрытие через `<AdvancedOnly>` / `<TechOnly>`.

## Этап 6 — Расширенный итог (разделы 31-33)

- Доработать `BoxPriceBreakdown` (или создать `MultipageSummary`) — добавить: цена за штуку, срок, печатные листы, закупочные листы, печатный формат, отходы, кол-во форм, краткий маршрут.
- Сделать так, чтобы каждая цифра имела tooltip «откуда взялась» (ссылка на этап расчёта).

- Новые файлы: `src/lib/calc/multipage/context.tsx`, `route.ts`, `validate.ts`, `spring.ts`, `composition.ts`; `src/components/calc/multipage/ModeSwitcher.tsx`, `BlockEditor.tsx`, `RouteTimeline.tsx`, `TechReport.tsx`, секции в `sections/`.

- Тип `ProductType` не трогаем — изменения только в слое UI/состояния.
- БД не трогаем на этих этапах: всё в локальном состоянии шаблонов. Когда дойдём до сохранения расчётов в БД с новой структурой — отдельная миграция.
- Совместимость: текущие сохранённые расчёты должны открываться (миграция state при загрузке).
