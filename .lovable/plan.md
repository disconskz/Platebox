# Подключение формул справочника к шаблонам

## Проблема

В справочнике (Справочник → Операции) уже есть формулы расчёта стоимости и расхода: каталог операций, параметры с формулами, статьи работ с `price_source` и `quantity_source`. Эти формулы хранятся в базе и редактируются через построитель формул.

Универсальный калькулятор использует их корректно — через компонент выбора операций из каталога. Но **шаблонные калькуляторы** (Брошюра, Блокнот, Календарь и т.п.) полностью оторваны от справочника:

- цены бумаги и операций «зашиты» прямо в код,
- блоки шаблона хранят список операций как обычные строки-подписи, без связи с кодом операции в справочнике,
- изменение формулы в справочнике никак не влияет на расчёт по шаблону.

То есть две системы считают по-разному, и формулы из справочника фактически работают только в одном месте.

## Что предлагается сделать

### 1. Связать блоки шаблона с операциями справочника
В описании внутреннего блока шаблона хранить **коды операций** из справочника (а не свободные подписи). Для каждой операции в блоке можно задать значения её параметров (или оставить значения по умолчанию из справочника).

### 2. Единый механизм расчёта по формулам
Сделать общий модуль, который:
- загружает из базы каталог операций, их параметры и статьи работ,
- подставляет значения параметров (тираж, формат, количество и т.д.),
- вычисляет количество и цену каждой статьи по формулам из справочника,
- возвращает готовые строки спецификации (название, кол-во, цена, сумма).

Этот модуль уже фактически реализован в выборе операций каталога — его нужно вынести в переиспользуемый вид.

### 3. Заменить «зашитые» расчёты в шаблонах
В шаблонных калькуляторах (Брошюра в первую очередь, затем Блокнот, Календарь, остальные) заменить хардкод по операциям (ламинация, биговка, фальцовка, скрепление, упаковка и пр.) на вызов общего механизма. Сама геометрия раскладки (сколько изделий на лист, число печатных листов) остаётся локальной — её в справочнике нет.

### 4. Материалы — отдельным шагом
Цены бумаги сейчас тоже зашиты в шаблоне. Их стоит подтягивать из справочника материалов — но это отдельная задача, не обязательная для текущей.

## Результат

- Любая правка формулы в справочнике сразу отражается во всех шаблонных калькуляторах.
- Цены и расходы по операциям считаются одинаково в универсальном и шаблонных калькуляторах.
- В шаблоне видно, из каких операций справочника собрана стоимость каждого блока.

## Что менять (для разработчика)

- `src/lib/calc/multipage/blocks.ts` — поле `InternalBlock.operations: string[]` → коды операций + значения параметров.
- Новый `src/lib/calc/operations-runtime.ts` (или хук `useOperationCost`) — выносим логику из `src/components/calc/CatalogOperationsPicker.tsx` (загрузка `operation_catalog` / `operation_parameters` / `operation_work_items`, `evalFormula` из `src/lib/operations/formula.ts`).
- `src/components/calc/multipage/BrochureCalculator.tsx` — заменить хардкод-`push(...)` в блоке расчёта на результаты нового механизма; начать с послепечатных операций.
- Затем по той же схеме: `NotepadCalculator`, `DeskCalendarCalculator` и остальные шаблоны через `MultipageTemplateHost`.

## Уточняющие вопросы

1. Начать с одного шаблона (Брошюра) как образец, потом перенести на остальные — или делать сразу все?
2. Подключать только послепечатные операции из справочника, или вообще все статьи расчёта (включая печать, приладку, упаковку)?
3. Материалы (бумага) — оставить пока зашитыми или тоже выносить в справочник в рамках этой задачи?
