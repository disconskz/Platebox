## Что делаем

Для видов **Брошюра** и **Журнал** разделяем форму «Новый расчёт» на два независимых блока, расположенных подряд:

1. **Обложка** — отдельная бумага/плотность, формат и раскрой, красочность, припресс/ламинация, тиснение, конгрев.
2. **Внутренний блок (тетрадь)** — текущие поля для страниц.

Для остальных видов поведение не меняется.

## Архитектура

### 1. Тип данных и состояние (`Calculator.tsx`)

Новая структура `CoverSpec`:
```ts
{
  paperId: string;        // отдельная бумага обложки
  density: number;        // г/м²
  format: string;         // обычно равен формату изделия
  customW/H: number;      // если "Custom"
  colorsFront: 0|1|2|4;
  colorsBack: 0|1|2|4;
  lamPrepress: boolean;   // плёнка
  lamSide: "1"|"2";
  pouchLam: boolean;
  stamping: boolean;      // фольга
  congrev: boolean;
  // Параметры тиснения/конгрева переиспользуют существующие state как «обложечные»
}
```
Хранится в одном `useState<CoverSpec>`. Гейтим через новый `caps.cover: boolean` (true только для `magazine` и `brochure`).

### 2. Капабилитис (`src/lib/calc/capabilities.ts`)

Добавляем поле `cover: boolean`. Включаем для `magazine`, `brochure`. Для `book` пока не трогаем (там твёрдый переплёт со своей логикой). Существующие флаги (`lamPrepress`, `stamping`, `congrev`) у `magazine`/`brochure` тогда относятся к **тетради** (внутреннему блоку), а cover-поля живут внутри блока обложки.

### 3. Калькуляция

Внутри `useMemo`, считающего себестоимость, для брошюры/журнала:
- Считаем количество обложек = `циркуляция / спуск_на_листе_обложки` (обычно 1 обложка = 1 разворот = 2 страницы; листов = `ceil(circ / up)`).
- Добавляем `SpecItem` стадии `paper` с обложечной бумагой (отдельная строка «Бумага — обложка»).
- Добавляем строку допечатных «Формы — обложка» (по красочности обложки, отдельный приладочный лист).
- Добавляем строку печати «Печать — обложка» (тираж = листы обложки × красок).
- Если включена обложечная ламинация / припресс / тиснение / конгрев — пересчитываем эти блоки на **площадь/тираж обложки** и добавляем как отдельные `SpecItem` с пометкой «(обложка)».

Текущие расчёты тетради остаются как есть — они уже считают «внутренний блок».

### 4. UI

В форме после блока «Продукция и параметры» при `caps.cover === true` рендерим два сворачиваемых, по умолчанию раскрытых блока:

```text
┌─ Обложка ─────────────────────────┐
│ Бумага / плотность / формат       │
│ Красочность 4+0 / 4+4 / …          │
│ ☐ Припресс плёнкой   ☐ Ламинация   │
│ ☐ Тиснение фольгой   ☐ Конгрев     │
└────────────────────────────────────┘
┌─ Внутренний блок (тетрадь) ───────┐
│ (существующие поля)                │
└────────────────────────────────────┘
```

Существующая «бумага/плотность/красочность» для брошюры/журнала переименовывается в подпись «Внутренний блок (тетрадь)», чтобы не было путаницы.

### 5. Что НЕ трогаем
- Книгу (`book`), блокнот, календари — отдельная задача.
- AI-ассистент, шаблоны, схему БД — структура `calculations.specification.cover` JSONB-совместима.
- Spreadsheet/PDF-экспорт получит строки автоматически (они идут по `SpecItem[]`).

## Шаги

1. `capabilities.ts` — добавить `cover` в интерфейс и включить для `magazine`/`brochure`.
2. `Calculator.tsx` — добавить `coverSpec` state + reset при смене типа продукции / применении шаблона.
3. `Calculator.tsx` — отрендерить блок «Обложка» (бумага, плотность, формат, красочность, чекбоксы) перед блоком «Внутренний блок» при `caps.cover`.
4. `Calculator.tsx` — в `useMemo` себестоимости добавить ветку, генерирующую `SpecItem[]` для обложки (бумага, формы, печать, отделка).
5. Загрузка/сохранение расчёта — сериализовать `coverSpec` в `specification.cover`.
6. Smoke-проверка: открыть брошюру 1000 шт A4 — оба блока видны, итог растёт после включения обложки.
