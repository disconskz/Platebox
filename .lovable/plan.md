## Цель

Сделать справочник полноценным центром управления: дублирование/массовое удаление/поиск/CSV, подгруппы и пользовательские справочники, а также вынести **все** зашитые в коде правила расчёта (припуски, приладка, цены формы/резки/упаковки, выбор форматов и оборотов) в редактируемый UI, чтобы калькулятор полностью настраивался без программиста.

---

## 1. Действия над строками (во всех таблицах справочника)

В каждую таблицу `RefTable` добавляем:

- **Дублировать** — кнопка-иконка в строке: создаёт копию записи (без `id`/`created_at`), к `name` добавляется « (копия)».
- **Массовое удаление** — колонка чекбоксов + панель действий сверху («Выбрано N · Удалить») с подтверждением.
- **Поиск/фильтр** — поле поиска над таблицей, фильтрует по всем текстовым колонкам и подписям select-значений (русским).
- **Импорт/экспорт CSV** — две кнопки в шапке таблицы:
  - Экспорт: текущие строки → CSV (UTF-8 BOM, разделитель `;`, заголовки = русские названия колонок).
  - Импорт: парсинг CSV, превью изменений (новые/обновлённые), затем `upsert` в Supabase.

Кнопка «Удалить» в строке остаётся, но переезжает в выпадающее меню «⋯» вместе с «Дублировать», чтобы строка не стала шире.

## 2. Разделы справочника

Делаем два уровня:

**A. Подгруппы внутри существующих таблиц (быстро).**
Добавляем поле `subgroup` (где его ещё нет — у `materials`, `equipment`, `lamination_prices`, `print_formats`, `purchase_formats`, `envelope_formats`). В UI:
- Над таблицей — список «разделов» (значений subgroup) с кнопкой «+ Раздел» (создаёт пустой раздел = просто сохраняет имя в новой служебной таблице `reference_sections(table_key, name, sort_order)`, чтобы пустой раздел не исчезал).
- Клик по разделу фильтрует строки; «Все» — без фильтра.
- При добавлении строки текущий раздел подставляется в `subgroup`.
- Переименование/удаление раздела через меню «⋯» рядом с названием.

**B. Свои справочники (новая сущность).**
Новая таблица `custom_references`:
```
id, name, slug, fields jsonb  -- [{key,label,type:'text|number|select|ref',opts?,refKey?}]
```
и `custom_reference_rows(reference_id, data jsonb)` для строк.

В UI справочника появляется отдельная вкладка **«Свои справочники»**:
- Список созданных справочников + «Создать справочник» (имя + конструктор полей).
- Каждый кастомный справочник открывается тем же `RefTable`-компонентом (универсализируем его для работы с jsonb).
- Кастомные справочники доступны для выбора в калькуляторе как источники значений (через тип поля `ref → custom:<slug>`).

## 3. UI правил расчёта

Создаём новую вкладку **«Правила расчёта»** в `/references` со следующими секциями (каждая — карточка с формой, сохранение в `system_settings` по ключам).

**3.1 Поля и припуски** (`rule.layout.*`)
`marginLR`, `marginTop`, `marginBottom`, `bleed`, `stickerGap`, `stickerEdge` — мм, числовые поля с подсказками.

**3.2 Приладка / отходы / коэффициенты** (`rule.setup.*`)
`setupOwn`, `setupForeign`, `setupPercent` (%, отображаем как 1.0 = 1%), `bagMinSetup`.

**3.3 Цены: формы, краска, резка, упаковка** (`rule.price.*`)
`formCost`, `formPrepCost`, `cutCostPerSheet`, `finishCutCost`, `numberingCost`, `designCost`, `stampingSetup`, `stampingClicheMin`, `stampingClichePerCm2`, `stampingImpr`, `stampingImprNotebook`. У каждого — единица измерения и пояснение.

**3.4 Правила выбора форматов и оборота** (`rule.formats.*`)
- Список приоритетных закупочных форматов (drag-n-drop порядок) — заменяет `maxPrintW/H` + `altPrintW/H`. Источник — таблица `purchase_formats`, добавляем чекбокс «Использовать в авто-подборе» и поле «Приоритет».
- Глобальный переключатель «Включить оборот СТФ (work-and-turn)» и порог тиража, с которого его предлагать.
- Правила лимита по типу продукта/тиражу/формату — это уже есть в `press_machines` и `product_circulation_rules`; добавляем перекрёстную ссылку «Открыть таблицу» с этой вкладки.

**3.5 Кнопка «Сбросить к заводским»** — возвращает значения из `DEFAULTS`.

### Подключение к движку

`engine.ts` сейчас читает `DEFAULTS` напрямую. Делаем:
1. Загрузчик `loadCalcRules()` — один запрос к `system_settings` с префиксом `rule.*`, кешируется в React Query.
2. `runCalculation(input, rules)` принимает правила параметром; в коде заменяем `DEFAULTS.x` на `rules.x` (с `DEFAULTS` как fallback, если ключ ещё не задан в БД).
3. В `Calculator.tsx` передаём загруженные правила в `runCalculation`.

## Технические детали (для разработчика)

**Миграции:**
- `reference_sections(id, table_key text, name text, sort_order int)` + RLS (read auth, write admin).
- ALTER TABLE для `subgroup text` на таблицах, где его нет.
- `custom_references`, `custom_reference_rows` + RLS.
- Сидируем `system_settings` ключами `rule.layout.marginLR` … со значениями из `DEFAULTS`.

**Файлы:**
- `src/pages/References.tsx` — рефакторинг `RefTable` (вынести в `src/components/references/RefTable.tsx`), новые подкомпоненты `RowActionsMenu`, `BulkBar`, `SearchBar`, `CsvIO`, `SectionsBar`.
- `src/pages/References.tsx` — добавить вкладки «Правила расчёта» и «Свои справочники».
- `src/components/references/CalcRulesEditor.tsx` — формы 3.1–3.4.
- `src/lib/calc/rules.ts` — типы `CalcRules`, `loadCalcRules`, маппинг `system_settings → CalcRules`.
- `src/lib/calc/engine.ts` — параметризовать `runCalculation`, заменить прямые `DEFAULTS.*`.
- `src/pages/Calculator.tsx` — `useQuery(['calc-rules'])` + прокидывание в расчёт.

**CSV:** библиотеку добавлять не будем — пишем мини-парсер (RFC 4180, разделитель `;`).

**Тесты:** обновить `engine.test.ts` — передавать `DEFAULTS` явно, добавить пару тестов на «правило переопределяет».

## Что НЕ входит в этот шаг

- Версионирование правил и пресеты «Эконом/Стандарт/Премиум» (можно добавить позже как отдельную таблицу `calc_rule_presets`).
- Полный визуальный конструктор формул — правки только параметров, формулы остаются в коде.
- Аудит изменений (кто/когда менял правило).
