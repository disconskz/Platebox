# Аудит UI/UX и backend (18 мая 2026)

## Ключевые баги и риски

### 1) Критично: публичный CORS и отсутствие обязательной авторизации в Edge Function
- В `supabase/functions/ai-assist/index.ts` явно указан `Access-Control-Allow-Origin: *`, а в комментарии написано, что endpoint публичный (`no auth required`).
- Это позволяет вызывать функцию с любого домена и повышает риск злоупотребления API-кредитами и DoS по rate-limit.

**Что улучшить:**
1. Ограничить CORS белым списком доменов (prod/stage).
2. Сделать обязательной проверку JWT (или service token + внутренний proxy).
3. Ввести server-side rate limiting по user_id/IP.

### 2) Высокий: отсутствует проверка ошибок запросов в ряде сценариев
- Во многих местах данные записываются/читаются без обработки `error` от Supabase (`load`, `saveEdit`, `updateMargin`).
- Пользователь может видеть «успешное» состояние при частично проваленных операциях.

**Что улучшить:**
1. В каждом запросе обрабатывать `error`, показывать `toast.error` и откатывать optimistic UI.
2. Вынести обёртку `safeQuery`/`handleSupabaseError` для единообразия.

### 3) Высокий: невалидные пользовательские значения цен и маржи
- Вручную редактируемая цена приводится через `Number(editValue)` без проверки диапазона и `NaN`.
- Аналогично, маржа может быть установлена в некорректное значение.

**Что улучшить:**
1. Добавить zod-валидацию: цена > 0, конечна, разумный max; маржа в диапазоне (например, 0..500).
2. Блокировать сохранение при некорректном вводе и подсвечивать поле.

### 4) Средний: потенциальный race-condition при последовательных обновлениях расчёта
- `saveEdit` делает несколько независимых запросов: update item -> insert adjustment -> update totals -> reload.
- При параллельных правках разных строк возможна потеря актуальных итогов.

**Что улучшить:**
1. Перенести пересчёт totals в RPC/transaction на сервере.
2. Использовать версионирование записи (`updated_at` guard) или row-level locking в SQL функции.

### 5) Средний: UX-проблема загрузки/ошибок в защищённых страницах
- На защищённом маршруте есть только «Загрузка…», но нет явного fallback при сбое получения сессии/данных.

**Что улучшить:**
1. Добавить состояние `error` в auth/provider и retry-кнопку.
2. Для страниц расчёта сделать skeleton + пустые состояния + CTA.

## Дополнительные UX-улучшения

1. **Inline-валидация формы логина/регистрации** (не только toast) с текстом под полями.
2. **Подтверждение опасных действий** (удаление расчёта, массовые правки).
3. **Индикаторы прогресса** на действиях экспорта (Excel/PDF) и блокировка кнопок во время выполнения.
4. **Доступность (a11y):** проверить контраст и клавиатурную навигацию для иконок-кнопок редактирования.
5. **Наблюдаемость:** добавить централизованный лог ошибок клиента (Sentry/LogRocket) и correlation-id для backend.

## Приоритетный roadmap (коротко)

- **P0 (1–2 дня):** закрыть публичный CORS/JWT, добавить базовый rate-limit и строгую обработку `error`.
- **P1 (2–4 дня):** валидация цен/маржи + транзакционный пересчёт totals через RPC.
- **P2 (3–5 дней):** улучшения UX-состояний (loading/empty/error), a11y и прогресс экспорта.
